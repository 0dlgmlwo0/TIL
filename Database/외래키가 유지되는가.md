# 📘 오늘 질문한 DB 관련 내용 정리 (2025-05-16)

---

## ✅ hospital_main과 hospital_detail 관계

- `hospital_main.hospital_code`: **Primary Key**
- `hospital_detail.hospital_code`: **Foreign Key** (참조 대상은 main)

- 두 테이블은 **1:1 또는 1:N 관계**
- 데이터베이스 설계상 `hospital_main`이 **기준 테이블**이고, `detail`은 부가정보

---

## ✅ hospital_detail 코드 정리 및 동기화 전략

### 🔹 목표
- `hospital_main`에 있는 `hospital_code`만 `hospital_detail`에도 존재하게 만들고 싶음
- 상세정보는 나중에 채울 계획

### 🔹 해결 쿼리

```sql
INSERT INTO hospital_detail (hospital_code)
SELECT hospital_code
FROM hospital_main
WHERE hospital_code NOT IN (
  SELECT hospital_code FROM hospital_detail
);
```

→ `main`에 있는 코드 중 `detail`에 없는 것만 추가

---

## ✅ detail의 코드 다 지우고 다시 채워넣기 (초기화 후 재생성)

### 방법 1. TRUNCATE

```sql
TRUNCATE TABLE hospital_detail;

INSERT INTO hospital_detail (hospital_code)
SELECT hospital_code
FROM hospital_main;
```

- 🔄 **테이블 전체 초기화**
- ✅ 외래키 관계 유지
- 빠르고 안전함

### 방법 2. DELETE (느리지만 제약 없음)

```sql
DELETE FROM hospital_detail;
```

- ✅ 외래키 유지됨
- 다만 행이 많으면 느림

### ❌ 잘못된 방법: NULL로 업데이트

```sql
UPDATE hospital_detail SET hospital_code = NULL;  -- ❌ 실패함
```

- 외래키 제약조건 때문에 오류 발생함

---

## ✅ 외래키(FK) 관계가 유지되는 조건 요약

| 작업 | 외래키 유지 여부 | 설명 |
|------|------------------|------|
| `TRUNCATE` | ✅ | 테이블 비우고 관계 유지 |
| `DELETE` | ✅ | 행 삭제, 관계 유지 |
| `UPDATE SET NULL` | ❌ | 외래키 위반 |

---

## ✅ 쿼리로 코드 일치 여부 확인

```sql
-- main에는 있고, detail에는 없는 hospital_code
SELECT hospital_code
FROM hospital_main
WHERE hospital_code NOT IN (
  SELECT hospital_code FROM hospital_detail
);

-- detail에만 있고, main에는 없는 (비정상 데이터)
SELECT hospital_code
FROM hospital_detail
WHERE hospital_code NOT IN (
  SELECT hospital_code FROM hospital_main
);
```
